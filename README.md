# 本地量子计算实验台

小规模、纯本地的量子线路实验台：Python 负责真实状态向量计算，React 负责线路编辑与结果展示。不依赖任何量子云服务。

## 启动

```bash
# 终端 1：后端 API（127.0.0.1:8000）
.venv/bin/python -m backend.server

# 终端 2：前端界面（127.0.0.1:5173）
cd frontend
npm run dev
```

打开 Vite 输出的本地地址即可。Vite 已配置 `/api` 代理到 Python 后端。

## 第一轮支持范围

- 量子位规模：1-4 个量子位。
- 初始状态：计算基态，如 `0`、`00`、`0101`。
- 单量子位门：`H`、`X`、`Y`、`Z`、`S`、`T`。
- 旋转门：`RX(theta)`、`RY(theta)`、`RZ(theta)`，角度使用弧度。
- 双量子位门：`CNOT(control, target)`、`CZ(control, target)`、`SWAP(a, b)`。
- 测量：`MEASURE(q)` 在后端执行计算基投影测量并归一化坍缩状态；后续门和测量使用坍缩后的状态。
- 随机种子：随项目线路保存；同一种子与线路可复现逐步测量和重复实验结果。
- 版本保存：线路保存到本地 `data/circuits.json`，同名再次保存会递增版本号。

非法范围（包括量子位越界、双位门两端相同、旋转角不是有限数值、初始基态格式错误等）由后端 `/api/validate` 校验；前端会标红对应步骤并禁止开始运行。

## 逐步执行

前端点击“开始并逐步执行”会在后端创建会话并立即执行第一步；会话状态保存在后端，继续点击“执行下一步”时，测量结果和坍缩后的状态会持续影响后续步骤。右侧实时显示每个计算基的概率和测量记录。

逐步请求进行中时按钮会被禁用，避免重复点击产生竞态；线路执行完毕后再次点击“下一步”不会报错，后端幂等返回最终快照并给出明确提示。固定种子下，逐步执行与 `/api/simulate` 一次运行的测量序列、每一步概率完全一致。

## 中途保存、恢复与条件分支实验

- 逐步执行过程中可随时点击“保存当前状态”。保存点包含坍缩后的状态向量以及随机数生成器（RNG）的内部状态，存于后端内存。
- “从保存点继续”会创建新会话：之前已发生的测量结果原样保留，不会因为恢复而重新抽取；后续测量从保存时的 RNG 位置继续。
- “中途测量后的条件分支实验”允许在同一保存点上配置最多 8 条后续方案。所有方案共用保存点之前的线路、坍缩状态和测量事实；后续门、分支 RNG、批次、计数和频率完全独立。
- 创建实验时可为每个方案设置初始样本预算；运行到预算后会立即原子保存到 `data/branch-experiments/<experiment_id>.json`。文件包含共同前缀、前缀测量、各分支条件步骤、计数、样本批次和分支 RNG 状态。
- 可以输入实验 ID 单独恢复结果，也可以只向其中一个方案继续追加样本。新样本使用该方案保存的 RNG 状态继续生成，并记录为独立批次；不会重放或改动其他方案，也不会把不同条件下的样本合并成一批。
- 分支基础随机种子由实验保存，分支 RNG 由“基础种子 + 分支 ID”确定性派生。因此改变分支运行顺序、先追加哪个方案，或把同一个实验 JSON 复制到另一个保存位置，恢复后追加样本都得到相同的可重放序列。
- 旧的单次轨迹比较仍可通过 `/api/checkpoints/<checkpoint_id>/compare` 调试单条轨迹；统计判断使用条件分支实验接口 `/api/checkpoints/<checkpoint_id>/branch-experiments`。

## 测量结果条件筛选

- 每个方案可为分支线路中的任意 `MEASURE` 步骤设置筛选条件（`filters: [{step, outcome}]`），只统计中途测量结果命中条件的尝试；同一方案可在不同测量位置连续设置多个筛选。
- 结果同时展示总尝试数、通过筛选数（及通过率）和条件分布，并标明每个统计对应的样本范围；条件分布只基于通过筛选的样本，不与未命中样本混合。
- 筛选没有命中时明确提示“没有证据”，条件分布显示为不可用（`frequencies: null`），不会显示成全零概率结论。
- 筛选条件是方案定义的一部分：修改条件需另建方案，旧条件样本不会并入新条件；不同筛选条件的方案可在同一保存点上并排比较。
- 追加预算时尝试身份由分支随机流位置决定，暂停、恢复或更换保存位置后继续追加不会重复计数，也不会改变可重放结果。

重复实验统计走独立接口与独立 RNG，不会消耗或串改任何交互会话/保存点的随机数状态。

## 自适应采样预算分配（序贯研究）

在条件分支实验之上，可以创建“研究”（adaptive study）：开始前一次性指定关心的条件概率事件、精度目标与总尝试上限，之后由系统按证据不足程度逐批分配预算，而不是给每个分支固定追加同样数量。

- 创建研究：`POST /api/branch-experiments/<experiment_id>/studies`，参数包括 `mode`（`estimate` 观察单个分支 / `compare` 比较两个分支的事件概率差）、`event.basis_states`（关心事件对应的计算基态集合）、`epsilon`（允许误差）、`delta`（置信参数，默认 0.05）、`total_budget`（总尝试上限）、`batch_size`（每批追加量）。
- 推进研究：`POST /api/studies/<study_id>/advance` 执行一轮（先判断停止，再向证据最不足的分支追加一批）； `POST /api/studies/<study_id>/run` 一直运行到停止或预算耗尽；`GET /api/studies/<study_id>` 读取当前快照。
- 停止判断使用时一致（time-uniform）Hoeffding 置信序列：任意时刻、任意多次查看以及按已有结果自适应分配预算时结论都有效，不会把一次固定样本量的把握程度当成反复提前停止后的保证。比较模式对两个分支各用 delta/2 做 Bonferroni 合并。
- 每一轮的继续/停止原因都写入持久化决策日志（`data/adaptive-studies/<study_id>.json`）：为什么继续、预算分给了哪个分支、为什么停止，全部可追溯；暂停、重开或改变分支执行顺序后日志与分支 RNG 状态继续衔接，不重抽、不漏记。
- 带筛选的分支分开报告两种不确定性：`acceptance_uncertainty`（接受率的置信序列半径，基于全部尝试）与 `conditional_uncertainty`（接受后条件分布的半径，只基于命中样本）。筛选没有命中时条件分布仍是“没有证据”（`has_evidence: false`，估计与半径为 `null`），研究会继续把预算分给该分支或最终在预算耗尽时保留未确定。
- 预算耗尽仍不能按 epsilon 区分时，研究状态为 `undecided` 并保留未确定，不会为了给出赢家改用其他统计口径；比较模式下另有 `branch_a_greater` / `branch_b_greater` / `within_epsilon`（区间整体落在 ±epsilon 内）三种定论。
- 研究规格（事件、epsilon、delta、预算）创建后不可变：修改精度目标或关心事件需要创建新研究（新的 study_id 与独立日志），历史研究文件仍按原条件读取；新研究复用同一分支随机流，不会重抽已有尝试。

## 样例与核对

- 单量子位样例：`|0>` 后接 `H`，理论概率为 `P(0)=P(1)=0.5`。
- 关联量子位样例：`H(q0)` + `CNOT(q0,q1)` 产生 Bell 态，理论概率只有 `|00>` 与 `|11>`，各为 0.5；先测量 q0 后，q1 的结果必然与 q0 相同。
- 重复实验可设置 1-100000 次，柱状图同时展示实测频率和后端给出的理论概率。
